# ИИ Арт студия — Документация

Единое окно генерации игрового арта на локальном ComfyUI: иконки сущностей и элементы
интерфейса (панели, кнопки, рамки). История вариантов, неразрушающая постобработка,
публикация прямо в игру с синхронизацией USS.

Меню: **ProtoSystem → ИИ студии → ИИ Арт студия** (класс `IconStudioWindow`,
сборка ProtoSystem.IconGen.Editor), кнопка «🎨 Арт» в главном тулбаре.
Как подключить студии в новом проекте — `Documentation~/AIStudios.md` пакета.

## Архитектура

**Принцип:** ядро не знает про игру. Вся привязка — данные и колбэки в `ArtContentItem`.
Новый набор арта = реализовать `IArtContentProvider` + создать `IconCollectionAsset` +
добавить его в `IconStudioConfig`. Кода студии не касаемся.

Библиотека вариантов ищется по типу (первая в проекте), у Last Convoy —
`Settings/Meta/IconVariantLibrary.asset`. Папки паков и референсов стиля — поля библиотеки
(`packsFolder`, `styleRefsFolder`; пусто — подпапка рядом с библиотекой).

## Быстрый старт

1. **Поднять ComfyUI.** В левой панели студии индикатор: 🟢 работает / 🔴 не запущен /
   🟡 проверка-старт. Кнопка «Запустить» поднимает сервер; файл запуска задаётся в
   **Project Settings ▸ AI Icon Tools ▸ «Запуск (.bat/.exe)»**.
2. **Выбрать вкладку** (набор) и сущность в гриде.
3. **Проверить промпт**: поле «Промпт» — это только `{subject}` (что нарисовано).
   Шаблон стиля и негатив — отдельные поля в левой панели («⤢ развернуть» открывает
   крупное окно).
4. **Сгенерировать** — «+N ещё» кладёт пачку в очередь. Каждая генерация = новый вариант,
   ничего не перезаписывается.
5. **Выбрать вариант** двойным кликом (одиночный — только выделение).

## Два вида арта

### Иконки сущностей
Фон вырезается (rembg), результат ужимается до размера хранения, опционально
пиксель-постпроцесс (сетка/палитра). Размеры-рендишены: одна сущность хранит спрайты под
разные размеры показа (`MetaIconLibrary`), окна берут ближайший не меньший.

### UI-элементы (панели, кнопки, рамки)
Отличаются принципиально — тянутся под разный размер через **9-slice**. Поэтому:

- `IsUiElement = true` → фон **не режется** и кадр **не обрезается** до контента
  (ветка `NoCrop` в `AiIconGenerator.SaveResult`), иначе съедет рамка;
- но результат **обязательно ужимается** до `StorageSize` (`ResizePng`);
- при импорте ставится `spriteBorder` + `SpriteMeshType.FullRect`;
- публикация копирует активный вариант в `ApplyToPath` — фиксированный PNG, на который
  ссылается USS.

## Постобработка (неразрушающая)

Настройки хранятся **у каждого варианта отдельно** (`IconVariant.postMode/postAxis/
postRect/postFillColor/postFeather/postCornerRadius`) и применяются **при публикации** —
варианты не плодятся.

| Режим | Что делает |
|---|---|
| **Оригинал** | весь кадр как есть |
| **Обрезать** | вырезать жёлтую область (отсечь фон/поля вокруг панели) |
| **Зеркалить** | отразить область в 4 стороны / по горизонтали / по вертикали |
| **Заливка центра** | залить область цветом со скруглением и мягким краем (feather) |

**Жёлтая рамка выделения** на картинке-исходнике — область-источник, тянется за два угла.
Зачем зеркало: диффузия плохо держит симметрию, а 9-slice требует одинаковых углов —
отражение одного угла решает это начисто.

Кнопка **«Создать вариант»** запекает текущую постобработку в новый вариант — так
операции складываются в цепочку (залил → создал → обрезал → …).

## Настройка 9-slice

Точные границы под конкретную картинку **автоматически не подобрать** — только глазом.
В примерке три инструмента, все синхронны:

- **зелёные линии** на исходнике — тянутся мышью, рядом цифры px;
- **поля** Слева/Справа/Сверху/Снизу — ввод числом;
- **растяжимое превью** — «Размер как в игре» ставит реальную высоту из USS-класса
  (+ выбор разрешения FHD/QHD/4K).

Правило: всё **внутри** линий (рамка, углы, заклёпки) не тянется; центр между ними
растягивается — держите его плоским и однородным.

## Связь с игрой (USS)

**Ключевой факт:** UI Toolkit берёт 9-slice из **USS** (`-unity-slice-*`), а `spriteBorder`
из `.meta` игнорирует (тот работает только для uGUI `Image`). Поэтому публикация правит USS.

Одна панель может оформлять **несколько классов** (`UssClasses`). Публикация во все разом:

- `background-image: url(...)` — иначе панель появится только там, где url вписан руками;
- `-unity-slice-*` — рамка;
- `-unity-background-image-tint-color` — наложение цвета (или удаляется);
- `background-color` — фон под панелью.

Пример (`UiArtLibrary.ArtContent.cs`): `panel_dieselpunk` → `building-card`, `resources`,
`back-button`, `tab-button`, `detail`, `base-row`; `button_action` → `card-action`,
`base-action`. Строки вкладок «Гараж»/«Локомотивы» (`base-row`/`base-action`) используют
ту же подложку, что карточки зданий и их кнопки.

Хелперы работы с USS — `IconVariantStore.ReadUssProp / WriteUssProp / SyncUssSlice /
TryParseUssColor / UssColor`.

## Грабли (выстрадано)

**Генерация и импорт**
- **Рендер 1024², а хранение 96.** `spriteBorder` задаётся в пикселях файла: рамка 24 px
  от 1024 — это ~2% кадра, срез уходит к краю и весь центр тайлится (мыло). UI-элементы
  обязаны проходить `ResizePng` до `StorageSize`.
- **rembg режет по контенту.** Для 9-slice это смерть — фиксированная рамка перестаёт
  совпадать. Отсюда ветка `NoCrop`.
- **Фон панели удобнее отсекать выделением**, а не rembg: он ИИ-сегментацией «съедает»
  светлые части рамки и обрезает не по всем сторонам.

**USS и UI Toolkit**
- **Button тянет фон и рамку из встроенной темы.** Просто удалить своё свойство мало —
  проступит дефолт. Нужно явно `background-color: rgba(0,0,0,0)` и `border-width: 0`.
- **Скроллер: слоёв больше, чем кажется.** Кроме трека и ползунка есть
  `unity-base-slider__dragger-border` — светлый, поверх ползунка.
- **Клик даёт фокус.** Глобальное `Button:focus { border-width: 2px }` рисует квадратную
  рамку поверх скруглённого спрайта — у панельных элементов фокус переопределяем
  (оттенок + сдвиг/масштаб), но **не убираем**: видимый фокус обязателен для геймпада.
- **Двойная рамка/фон.** Если панель принесла свою рамку — CSS-бордюр и `background-color`
  у класса убираем, иначе рисуются поверх, а прямоугольный фон просвечивает за
  скруглёнными углами.
- **tint умножает.** Белый = без изменений; «ярче» относительно белого не сделать —
  для подсветки берите оттенок или приглушайте базовый.
- **`translate` для выделения ломает вид** — элемент уезжает под обрезку контейнера.
  Лучше `scale` (не влияет на layout) + запас в `margin`, иначе ScrollView срежет край.
- **flex сжимает соседей.** При длинном описании строка уровня «съезжала» —
  спасают `flex-shrink: 0` и фиксированная высота.

**Editor-код**
- **Локаль.** `float.Parse`/форматирование без `InvariantCulture` в русской локали дают
  запятую (`rgba(...,0,9)`) — USS ломается, парсинг падает `FormatException`.
- **Не дёргайте `Bump()` на каждое движение мыши.** Пересборка пикера прерывает
  перетаскивание (теряется pointer capture). Постобработка пишется через `SetDirty` без `Bump`.
- **Кэш профилей.** `IconGenProfile.All()` кэшируется — новый ассет, созданный в обход
  событий, не появится в списке, пока не сбросить кэш/переоткрыть окно.
- **Метаданные — из кода, не из записи.** Пути публикации и USS-цели берутся из провайдера:
  старые записи ассета, созданные до появления полей, остаются пустыми.

## Профили и стили

- **`IconStylePreset`** — `positiveTemplate` с `{subject}`, `negative`, параметры сэмплера,
  пиксель-постпроцесс.
- **`IconGenProfile`** — совместимый набор «стиль + чекпоинт + LoRA», плюс журнал неудач.

Что реально влияет на результат:
- `even soft lighting` в промпте **провоцирует градиент** — для плоских панелей убирать,
  а в негатив класть `gradient, vignette, glow, shading`;
- `art-deco / ornate / elegant golden` вытягивают **барочную** рамку вместо тонкой;
- базовый `sd_xl_base_1.0` слабее дообученных — для чистого UI лучше `juggernautXL` с
  жёстким негативом, чем base;
- абсолютно плоскую заливку диффузия не даёт **никогда** — центр надёжнее залить
  постобработкой («Заливка центра»).

## Полезное

- **Ссылки на ассеты** в примерке: «Спрайт варианта» (PNG активного) и «В игре»
  (опубликованный) с кнопками «Показать» — подсвечивают файл в Project. Плюс пункт
  контекстного меню варианта «Показать PNG в проекте».
- **Паки** — снапшот выбранных вариантов по набору; двухэтапная чистка (сначала PNG,
  рецепты живы → потом рецепты).
- **Рецепты** переживают удаление картинок: любой вариант перегенерируется точь-в-точь.
- **Атлас**: вставка листа из буфера с умной нарезкой по «островам» непрозрачности,
  вырез фона rembg или заливкой от краёв.

## Рецепт: панель с нуля

1. Поднять ComfyUI (индикатор зелёный).
2. Вкладка **UI: Панели** → сущность → профиль «UI Panel Clean» → «+4 ещё».
3. Выбрать удачный вариант (двойной клик).
4. Режим **Обрезать/Зеркалить**, жёлтой рамкой выделить угол панели без полей —
   смотреть живое превью.
5. При необходимости **Заливка центра** (плоский тёмный центр, мягкий край) →
   «Создать вариант».
6. Подогнать зелёные линии 9-slice, «Размер как в игре» — проверить растяжение.
7. **«Применить в игру»** — спрайт и USS всех привязанных классов обновятся.
8. В USS у этих классов убрать свои `background-color`/`border`, состояния перевести
   на оттенок/масштаб.
